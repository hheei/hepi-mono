# apply_patch 语义与发布安全改进计划

## 目标与范围

补齐现有 V4A 输入的实际执行语义，避免准备期间的外部修改被直接覆盖，并保留文件换行风格。本次不替换 mpatch、不改变逐路径/逐 hunk 部分成功契约，不新增 grammar 或 dry-run 参数。

## 边界与契约

- pi-ext-tools 拥有 V4A 锚点、EOF 定位、纯移动和发布前基线核对；native mpatch 继续拥有匹配与取消。
- `@@ 文本` 限定后续 hunk 的搜索范围；缺失锚点不能退回无约束全文匹配。范围内重复上下文仍拒绝歧义。
- 支持没有内容 hunk 的 `Update File` + `Move to`，以及 `*** End of File` 的末尾定位语义。
- 对已读取源文件，在实际发布前重新核对基线。发现变化时保留外部内容并返回确定的拒绝；移动不得因源冲突删除外部修改。
- 基线核对属于尽力而为的冲突检测，不是文件系统 compare-and-swap；检查后到 rename/remove 之间仍有竞态窗口。锁仅协调遵守同一协议的调用。
- 更新保留原文件 LF/CRLF 风格及末尾换行状态；混合换行应避免无关行被全局归一化。
- 不改变 SSH 授权、取消、Unconfirmed、结果快照与 persistence 的所有权。临时文件必须清理，已确认发布的路径不回滚。

```text
V4A parse -> 约束范围内 staging -> 基线复核 -> Publish -> 实际 Outcome
                                      | 冲突
                                      +-> Rejected，保留外部内容
```

## 实施步骤

1. 检查 parser、staging、FS adapter 与现有测试，确定最小内部合同。
2. 补锚点、EOF 与纯移动的解析、执行及回归测试。
3. 补发布前源基线复核，覆盖 Update/Delete/Move 的外部修改与清理。
4. 保留原始换行，覆盖 CRLF、LF、无末尾换行与多 hunk。
5. 运行聚焦格式、测试与类型检查；涉及跨包合同则运行完整测试。
6. 用真实临时文件执行上述路径，确认结果与文件内容；更新当前架构说明，移除实现后失效的说明。

## 验收

- 重复函数体用锚点正确定位；不存在的锚点不改文件；未消歧的重复上下文仍拒绝。
- EOF 限定末尾，纯移动保留字节且遵循现有目标覆盖限制。
- 可控的读取后外部改写不会被发布覆盖，也不会被 Move/Delete 删除。
- CRLF 更新不把未修改内容转换为 LF；末尾换行符合上述合同。
- 既有部分成功、取消、SSH 不确定结果与稳定 diff 测试保持通过。

## 实施结果

- 已完成 V4A 锚点、连续锚点、EOF 与纯移动；native 匹配诊断恢复为全文件行号。
- 已完成临时文件写入后的源字节复核，以及 Move 目标发布后的源删除前复核。local 新目标使用不覆盖已有目录项的发布方式。
- 已完成 CRLF/LF、无末尾换行与混合换行上下文保留，保留 native fuzzy 的实际匹配跨度。
- 修改文件 Biome 检查通过；pi-ext-tools 独立 TypeScript 检查通过；最终扩展测试 38 个文件通过，323 项通过、21 项跳过。
- 最终 19 项真实文件场景通过，覆盖锚点定位、EOF 消歧、CRLF、无末尾换行、纯移动、缺失锚点拒绝、无锚点歧义拒绝、外部修改保留、混合换行、Unicode 字节偏移、EOF 与上下文组合、BOM、重复上下文、诊断坐标和取消后的临时文件清理。
- 仓库级检查未全绿：完整测试运行当时有 34 项失败，其中 1 项本次锚点诊断失败已修复并通过扩展复测，其余 33 项位于未改动的 pi-mctx。根 TypeScript 检查错误也位于 pi-mctx，未为通过检查改动无关代码。
- 验证使用仓库已安装的 Biome、TypeScript 与 Vitest Node 入口执行；未改依赖，也未重建未修改的 native bridge。没有进行真实 SSH 主机或 Windows/macOS 的运行验证。
