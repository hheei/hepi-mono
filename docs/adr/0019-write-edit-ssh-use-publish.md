# write/edit 在 SSH Target 上走 Publish，不另做 SFTP 写入

native Edit Mode 必须能改 SSH Target，但不能静默换成 apply_patch，也不能再做一条覆盖写入。`write` 与 `edit` 成为既有 Publish 的单 path 客户端：sibling temp + replace，复用 Changed / Rejected / Unconfirmed / NotApplied。远端 `edit` 保持 Pi native 精确匹配；远端 `write` 保持 Pi native 方言（没有就创建、有就覆盖、自动建父目录），不是 V4A Add/Update。SSH 路径是 Remote Path（相对 `$HOME` 或远端绝对路径），不是 apply_patch 的 lexical workspace。内容在锁内已相同则成功 no-change、不 Publish。SSH 上现有文件与 new bytes 仍受 ADR-0018 的 32 MiB 拒绝；本机 native 不因此加帽。本机 `write`/`edit` 仍走 Pi native execute；为开 SSH 不把本机迁到 Publish。Patch Core 已能 Publish；本变更实现远端 single-path client。一把 mutation lock 按 local workspace 或 SSH alias 串行化 apply_patch、write、edit；忙则拒绝，不排队，不挡外部写入。这修正 ADR-0018 里「锁只串行化 apply_patch」的范围。SSH header 为 warning 色 `host:path`，与 read 相同，不是 bash 的 `(host)`。Unconfirmed 用 warning `?`，不得把 diff 画成已写入，`isError: true`，并要求先 `read` 该 Target 上的该 path。SFTP 逾时跟 Publish：传输 ≤1 MiB 为 30s，否则 60s。
